## TL;DR
- **Best source to use now: OpenStreetMap (Overpass API).** It worked live and needs no key: 35 bakery/pastry shops and 79 cafés in the Municipality of Chalandri, every one with coordinates. Postal codes (5 of 35) and websites (3 of 35) are rarely filled in. Licence: ODbL (credit "© OpenStreetMap contributors").
- **Best official registry: GEMI Open Data API.** The terms allow our use (ODC-BY-1.0) and it returns VAT number, address, `zipCode`, `url`, email and activity codes (KAD). It **needs a personal `api_key`**. The public demo key `api-docs-key` was refused (HTTP 401) on every endpoint, `/health` included. A human must request a key.
- **The CSV fallback works** (REQ-PRS-007). The seeded `prospect_list_chalandri_bakeries.json` (18 rows, all in 15231-15234) and the OSM rows end up in one candidate CSV with the same columns.
- **Website scraping quality is good on real Greek shop sites.** Plain fetch → markdown returned products, brands, prices, opening hours and size signals from 4 real Chalandri businesses (3 bakeries, 1 café chain). **There is no Firecrawl key** in the workspace (no secrets at all), and Firecrawl is not a curated Integration Hub connector.
- Maps and review hosts are rejected by a host blocklist (REQ-PRS-005), tested in the proof.

### GEMI: exact API (from its live Swagger 2.0 spec at `https://opendata-api.businessportal.gr/api-docs`)
- Auth: `securityDefinitions.api_key = {type: apiKey, name: "api_key", in: header}`.
- Endpoints: `GET /companies`, `GET /companies/{arGemi}`, `GET /companies/{arGemi}/documents`, `GET /metadata/{activities|prefectures|municipalities|companyStatuses|legalTypes|gemiOffices|assemblySubjects}`, `GET /health`, `GET /downloadFile`.
- `/companies` query parameters: `arGemi, afm, name, legalTypes[], gemiOffices[], municipalities[], prefectures[], statuses[], isActive, activities[], resultsSortBy, resultsOffset, resultsSize (max 200)`.
- Company fields: `arGemi, afm, coNameEl, coTitlesEl[], municipality{id,descr}, city, street, streetNumber, zipCode, url, email, isBranch, objective, legalType, status, incorporationDate, activities`.
- Sample query for bakeries in Chalandri (not run: the key was refused):
  ```
  GET /metadata/municipalities            -> id for "ΧΑΛΑΝΔΡΙΟΥ"
  GET /metadata/activities                -> ids for KAD 10.71 (bread, fresh pastry), 47.24 (bread/pastry retail), 56.10/56.30 (cafés)
  GET /companies?municipalities=<id>&activities=<kad ids>&isActive=true&resultsSize=200&resultsOffset=0
      header: api_key: <GEMI_API_KEY>
  then keep rows with zipCode in {15231,15232,15233,15234}; paginate with resultsOffset
  ```
- Caveats: GEMI covers businesses registered in GEMI, so small sole traders may be missing. Greece moved to KAD 2025 on 2026-03-01, so check which code set `/metadata/activities` returns. Sending a function's `fetch` with `secretName` adds the key header for API Key secrets.

### OSM: exact query that worked
```
POST https://overpass-api.de/api/interpreter   (User-Agent: merc-spike/0.1)
data=[out:json][timeout:50];area["boundary"="administrative"]["name"="Δήμος Χαλανδρίου"]->.a;
(nwr["shop"~"^(bakery|pastry)$"](area.a);nwr["amenity"="cafe"](area.a););out center tags;
```
Result (HTTP 200, 28,839 B): 114 elements (cafe 79, bakery 32, pastry 3). For the 35 bakery/pastry shops: 31 named, 3 with a website, 5 with a postal code (15231 ×2, 15232, 15233, 15234), 3 with a phone. Every element has lat/lng, so "near route" scoring works without a postal code. Matching names include Βενέτη (×3), Τάσσης, Απολλώνιον, The Bakers, Κουλουράδες and Γκεκας.
Reliability: the first calls returned 502 ("server at capacity") on overpass-api.de and nothing on kumi.systems/private.coffee. A later retry succeeded. **The pipeline must retry with backoff, cache results per search, and fall back to the CSV.**

### Mapping to the `candidate` contract
`business_name ← name`, `lat/lng ← lat/lon or center`, `postal_code ← addr:postcode` (often null; can be derived from lat/lng via `postal_area` later), `phone ← phone|contact:phone`, `website ← website|contact:website` (after the blocklist), `external_source = "directory"`, `external_ref = "node/<id>"`. GEMI rows: `external_source="registry"`, `external_ref=arGemi`, `vat_number=afm`.

What did not work:
- Home pages built from images (Veneti) give only category names. You need 1-2 extra pages (catalogue, contact), so research should scrape the home page plus up to 2 linked pages (`/epikoinonia`, product category).
- Small shops often have no website (28 of 31 named OSM bakeries). Then the dossier is registry-only (GEMI) or only what the rep says, as REQ-PRS-003 expects.
- Prices are rare on bakery sites (no prices on Tassis, Bread B.C. or Veneti home pages). Café/chain menus have them.
- Closure notices are real, so "closed" text must be extracted and used as a disqualifier.

### Firecrawl
- Key presence: `wful secrets list` → `No secrets found.` (`--json` → `[]`). `global-variables list` → none. There is no `FIRECRAWL_API_KEY` locally either. **Firecrawl key: absent.**
- Integration Hub: `wful integrations connectors` lists 41 curated connectors and none is Firecrawl. `integrations connections` → none. So the options are (a) secret + `fetch` from a function, (b) a Custom MCP connection to Firecrawl's hosted MCP server, or (c) no Firecrawl: plain `fetch` + HTML→markdown in the function.
- API call once the key exists: `POST https://api.firecrawl.dev/v1/scrape`, `Authorization: Bearer fc-…`, body `{"url": "...", "formats": ["markdown"], "onlyMainContent": true, "timeout": 30000}` → `data.markdown`. From a function: `fetch(url, {method:"POST", secretName:"FIRECRAWL_API_KEY", body})` (a Bearer secret adds the header).
- Recommendation: plain fetch was enough for all 4 sites (server-rendered WordPress/WooCommerce/PHP). Build `scrape_website` as **function fetch + markdown conversion, with Firecrawl as an optional upgrade** when the secret exists. That takes Firecrawl off the critical path.
